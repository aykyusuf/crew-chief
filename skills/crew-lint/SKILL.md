name: crew-lint
description: "Manual checks that only report: scans CLAUDE.md, memory and agent files for stale standing instructions (a standing 'always delegate' line, a token-budget number, an absolute 'never' with no case), checks an agent brief for its stop rule, verification, output path and scope limit, and checks that the quotes in a research claims file or report really appear on their pages. Use when the user runs /crew-chief:crew-lint, asks whether their instruction files are out of date for newer models, or wants a brief or a set of sources checked before relying on it. Never edits a file on its own."
argument-hint: "[stale | brief <file> | sources <file or folder>]"
---

Manual lint with three local tools. Arguments: `$ARGUMENTS`. None of them edits anything or runs by itself (no hook): you run one when the user asks, show its output, and offer fixes. Edit a file only after the user says yes to that specific change. All tools need Node 22 or newer; if `node` is missing, say so in one line and stop.

- **`stale`** (or no argument): `node "${CLAUDE_PLUGIN_ROOT}/scripts/stale-scan.mjs"` scans `CLAUDE.md`, `CLAUDE.local.md`, `~/.claude/CLAUDE.md`, this project's auto-memory folder and the `agents/` folders; add paths as arguments to scan others (`--json` for machine-readable output). It prints `file:line: rule: text -> suggested fix` and a count; it never scans `STATUS.md` and never writes. Rules: `always-delegate` (a standing "always delegate" line makes the model delegate when it should not), `token-budget` (a token number in an instruction: state the scope and a stop rule instead), `absolute-never` (a "never" with no case or reason: name the case, or say "ask before X"; this is only a warning). Group the hits by file for the user, say which look like real problems and which are fine (a safety rule such as "never modify the project" often is), and offer to rewrite only the real ones. A line the user wants to keep can carry `crew-chief:keep` (on the line or the line above) and the scan skips it. The plugin's own agent files will show `absolute-never` warnings: report them, do not change them unless the user asks.
- **`brief <file>`**: `node "${CLAUDE_PLUGIN_ROOT}/scripts/brief-check.mjs" <file> --kind agent` (use `--kind research` for a research brief, `-` instead of a file to read standard input). Exit 0 means the brief has a stop rule, a verification step, an output path and a scope limit (an agent count, a search or call count, or a bounded scope; never a token number); exit 1 prints `missing: ...` with one suggested sentence per missing part and `error:` lines for a token number. Research briefs also get warnings for a missing objective, output format, assumption to verify and sources guidance. Offer to add the suggested sentences to the brief.
- **`sources <file or folder>`**: `node "${CLAUDE_PLUGIN_ROOT}/scripts/source-check.mjs" <claims.json | folder | report.md>` checks that each claim's quote appears on its URL. This makes web requests (read only: GET, private and loopback addresses refused, nothing sent but the URL and a generic user agent): say so once before running it. Stdout is a JSON array with one row per claim `{id, url, http, status, reason}`; status is `found`, `not_found` (page read, quote absent: the only refutation signal), `dead_link` (404, 410, no such host) or `unverified` (page could not be read: JavaScript page, PDF, 403, timeout, a quote under 20 characters; this is never a refutation). Page text is never printed. Show the rows grouped by status. The tool cannot judge whether a source supports a claim; for that, offer a verifier agent. For a Markdown report the claim pairing (a URL with the nearest following quote) is best effort: say so.

If the user gives an argument that is none of these, show the three forms in one line and ask which one they want.
