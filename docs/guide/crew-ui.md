# crew-ui: the band, the questions and the panes

A quiet band above the prompt, questions as buttons, agent panes, finish notices and click-to-open agents.

[← README](../../README.md) · [Türkçe](../rehber/crew-ui.md)

**On by default, and quiet.** A band above the prompt (terminal and Desktop app; VS Code keeps its status line) that draws nothing while there is nothing to say. A toast says so once after an update; `/crew-ui off` turns it off for good, `/crew-ui on` back on. It never writes to `settings.json`. It is a small part of the mod (`hooks/src/crew-ui.js`, layout in `hooks/ui-logic.mjs`).

- **First runs.** The first run of an agent type in a session is marked `first run` in the band, because a new agent or brief should be watched before it runs unattended.
- **Watching and overlap.** When more subagents run at once than `agents.warn` (default 5, [`/crew-config`](settings.md)) the band says so, because attention runs out before tokens do. When an Agent call for a writing agent (`implementer`, `implementer-hard`, `mechanic`) names files that another running writer's brief also named, the call's result carries a note (never a block): two agents editing one file collide. The files are found in the free-text brief by shape, so it is a hint, not a guarantee.
- **What it shows.** One line per running subagent (`deep-reader  Sonnet 5.5 ● ● ○ ○ ○ Medium ▓▓░░░░ 40%  12k  2m10s  reading auth`: the full model name, five effort dots, the effort word, the agent's own estimate, tokens, time; no tool call count), and a status line with the context (with a small graph of the last turns), the 5 h and 7 d limits, the guard, the saver and a compact key. The effort meter has five dots, one per level (`low` to `max`); `max` is a rainbow where colour is drawn.
- **Pictures on the Desktop app (`panel.style`).** Outside the terminal each running subagent is drawn as one small picture (an `Svg`, about 500×48 px, under 8k characters, no script, nothing loaded): a character, the same line of text, and a bar. `capsule` (default) is a yellow capsule buddy whose overalls, straps and goggle band take the model's colour; `cat` is a blue point kitten whose collar bell and beads take it. The agent type gives an accessory and a tool (`scanner` radar, `deep-reader` book, `implementer` hammer, `implementer-hard` gears, `reviewer` magnifier, `planner` drawing, `mechanic` wrench, `ui-tester` cursor; any other type a speech bubble), the model a colour (Haiku green, Sonnet blue, Opus orange, Fable violet, others grey), the effort the five dots and the pace (the higher the effort, the faster it moves). The bar is the agent's own `~pct` estimate: filled with a soft sheen while fresh, faded and marked `old` once stale, a sliding band with no number when it never sent one (no percentage is made up). The tokens and time slide to their new digit (about 300 ms) when they change. Only `transform` and `opacity` move, at most six parts per agent, and with reduced motion on nothing moves. The saver badge in the status line is a small leaf (`saver on`) or shield (`ultra-saver on`) there. Choose with `/crew-ui panel capsule|cat|text`, `/crew-config set panel.style ...` or `CREW_CHIEF_PANEL_STYLE`; `text` draws the line of text everywhere, no pictures. The terminal always gets the line. Not yet seen live on the Desktop app.
- **Quiet by default.** The band shows only what is worth a look: a running subagent, a limit from 70 %, something the guard stopped, a compaction due. With nothing to say it is not drawn. The context is not drawn at all; instead one toast appears the first time it passes the compaction size or 70 % of the window (again only after it has dropped below, e.g. after a compaction). `/crew-ui full` shows everything all the time, the context included (on the Desktop app as figures only, without the block graph). In the terminal, when you have a `statusLine` of your own, the full band leaves out the context and the limits (that line has them); the Desktop app has no such line and shows them. The compact key (`[1] compact`) is drawn only while no subagent runs (it comes back when they finish); outside the terminal (Desktop, VS Code, mobile) it says just `compact`, because the digit works only while the band has focus there, and you click it.
- **Looks.** `/crew-ui style boxed|plain|color|pills` (default `boxed`: a rounded frame); `/crew-ui demo on` draws sample content so a style can be judged without a busy session (on Desktop: a fresh, a stale and a missing estimate, and an agent type and model the pictures do not know).
- **Your questions as buttons.** While the band is on (it is by default), the plugin's own questions (compact, compact gate, limit and saver, advisor offer, limit reset, `/crew-tidy archive`) are asked in the band instead of a dialog: a lilac strip with `1 Yes  2 Not now ...`. Press the digit with an empty prompt (or `ctrl+x tab`, then the key). Nothing is held; unanswered, it expires to the safe answer after the usual 20 minutes. VS Code, a band that is off, or more than four answers use the old dialog. Claude's own questions (AskUserQuestion) are never touched. On the Desktop app (unless `panel.style` is `text`) the limit question is a card: the same text, answers, digits and order, a meter of the window with notches at 70, 80 and 90 %, a breathing leaf beside `Turn on saver` and a shield with one pulse ring and an `ULTRA` tag beside `Ultra-saver`. Every answer sits in the same frame (size, corner, border); they differ only in content, colour and the fill the frame takes under the pointer.
- **Small touches** (`/crew-ui extras off` to remove): the model and effort after the spinner word and before the turn line (`opus ●●○○○ · Baked for 3s`), a note in the footer's mode labels while the saver is on or the guard stopped something, a limit note after the prompt hint. `/crew-ui words on` also swaps the spinner word for a calm one by model (`Pondering`, `Working`, `Skimming`); off by default.
- **Agent finished.** When a subagent finishes, a toast says so (`implementer finished: 3:35 · 58k · 14 calls`: how long it ran, its last request's tokens, its tool calls; what is unknown is left out), and the same comes as a system notification through your own channel. Runs that end within 1.5 s of each other share one notice (`2 agents finished: implementer 2:00, scanner 0:30 ✗`). Not announced: a run shorter than `notify.min` (10 s; an error is always announced), a run you stopped, a teammate's turn, the engine's own forks. When the main turn ends right after, the system notification is left out (Claude Code raises its own then); the toast stays. Not tied to the band: `/crew-ui off` does not silence it, `/crew-config set notify.agent off` and `notify.native off` do ([settings](settings.md)).
- **Look inside an agent: `/crew-agents`.** A pane with this session's subagents, newest first (at most 15): running `⠋`, done `✓` or failed `✗`, name, model·effort, time, tokens. Click one to see inside it: its brief, its last 30 steps (what it wrote, each tool call with a short argument and the first line of the result) and, once it ended, its report on top. It refreshes while agents work (at most every 1.5 s), runs while a subagent works, and closes with Esc, `ctrl+x x`, `/crew-agents` again or `/crew-panel close`. The transcript is read only for the agent you picked, shown in the pane and nowhere else: never written, stored, logged or sent. An agent the session cannot read back (a pane-hosted teammate, an old run with no saved transcript) says so.
- **Panes.** `/crew-panel tasks` lists the project's `tasks.json`, `/crew-panel agents` draws a timeline of this session's subagents (when each started and ended, model, effort, tokens), `/crew-panel guard` lists what the command guard stopped, denied or warned. They open on request, refresh every two seconds, close with `ctrl+x x`, `/crew-panel close` or the same command again, and run while a subagent works.
- **Open an agent in the band (`panel.click`).** Outside the terminal a click on a subagent's row opens what it is doing right under it; another click closes it, and several can be open at once (at most 4; opening a fifth closes the oldest). A row drawn as a picture gets a small `▸`/`▾` button at its end (a picture cannot take a click itself); a row of text (`panel.style text`) is the button. No digit is bound to it (digits answer the band's questions); `ctrl+x tab`, Tab and Enter reach it. Under the row: its last 5 steps, one line each (the tool, a short argument, the first line of the result, or `›` and a line of its text), at most 120 characters; once it has finished its report comes first (6 lines) with its time, tokens and tool calls, and the row stays while it is open. The band never grows past what it has room for (`maxRows`) and adds at most 12 rows: the agent opened last is served first, older ones are cut (`… 3 more lines, in Full view`) or hidden until there is room. Below each: **Full view** puts the agent's whole transcript in the main view (`$.ui.view`), and while it is shown a *Back to the main chat* button sits at the top of the band. **While you view an agent, what you type in the prompt goes to that agent.** **Write** opens a small field: Enter sends it to the agent (`$.session.send`; never empty, at most 2,000 characters). A running agent reads it at its next tool turn. A finished agent is started again by a message, which costs tokens: its button says *Restart and send* and the band asks first (*Don't send* is the first answer and what 60 s without an answer means). Where the surface has no text field, *Write* opens the full view and you type in the prompt. The transcript is read when you open an agent and then only on its own events (at most every 1.5 s, never while drawing); it stays in memory while the agent is open, is shown only in the band, and is never written, stored, logged or sent; neither is a message. `/crew-config set panel.click off` (or `CREW_CHIEF_PANEL_CLICK=off`) keeps the rows as before; `/crew-agents` stays as it is. Not yet seen live on the Desktop app.
- **Where it was seen.** The band, the quiet and full modes, the `boxed` style, the turn-line touch and the effort meter were seen live in a terminal. The questions in the band, the panes, the spinner words, `color` and `pills`, the agent-finished notices and `/crew-agents` are covered by tests only so far.
- **Environment.** `CREW_CHIEF_UI=on|off` beats the saved choice.
- **Same as before.** Choosing `off` keeps the old dialogs for the questions and removes the small touches.
