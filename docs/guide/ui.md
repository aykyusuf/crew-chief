# UI work

How interface work is routed to `ui-implementer` with design skills, a UI profile, gates, references and a visual self-check.

[← README](../../README.md) · [Türkçe](../rehber/ui.md)

A task that builds or restyles an interface goes to `ui-implementer` instead of `implementer`. Its own default is Sonnet at medium, but the main session passes `model` and `effort` on every UI call from the table below. The rules come from `data/ui-policy.json`.

**Model and effort per UI call** (`models` in `data/ui-policy.json`; the UI hint and the routing skill repeat it; override one rule in `~/.claude/crew-chief-ui.json`):

| The UI work | model / effort |
|---|---|
| Small fix: 1-2 files, existing look | sonnet / medium |
| A component or screen with a reference image or a `DESIGN.md` | sonnet / high |
| Clear simple-to-mid UI work with a defined direction | opus / medium |
| A new landing, redesign or hero with no direction | opus / high |
| A new `immersive` scene | opus / high |
| A repair pass after a visual review | sonnet / medium; the same defect after two passes: opus / high |

Never Sonnet at xhigh (Opus high instead), never effort above high on UI work, never a Fable model unless you ask for Fable. For a big job (3 or more screens, a new site, a redesign) the main session starts with **`ui-designer`** (Opus, high, read-only): it reads the profile, references, ban list and polish checklist and writes one design spec (direction, palette with hex codes, type scale and pairing, grid, components, motion per the motion level, per-screen notes, acceptance checks) to `.crew-chief/design/<slug>.md`, no code; `ui-implementer` (Sonnet, high) then builds from the spec. `readonly-guard.sh` lets `ui-designer` write only a `.md` file under `.crew-chief/design/`. Under the saver an Opus call drops to medium; under ultra-saver a call that names Opus asks you first, and `ui-designer` called without naming Opus drops to Sonnet high without asking, like the other Opus agents.

**No Fable unless you ask.** `scripts/fable-gate.sh` (PreToolUse on `Agent`, every subagent, not only UI) denies the first Agent call whose `model` contains "fable" with a reason telling Claude to retry the identical call only if you asked for Fable in this conversation, otherwise to use Opus; the identical retry passes (remembered 4 hours by a hash in `${CLAUDE_PLUGIN_DATA}`). `CREW_CHIEF_FABLE_GATE=off` turns it off. The saver only ever rewrites a call to Sonnet. Not yet seen live (unit tests only).

**Not yet seen live.** The gate and the preload were seen in a probe plugin with `claude -p` (a plugin agent's `skills:` loads the plugin's own skills, and a `PreToolUse` hook on `Agent` fires, denies and shows the model its reason). The `ui-implementer` agent itself has not been run on a real UI task yet, so nothing here says how well it does the work, and the gate has not been seen in an interactive session. Check the agent's first report: its first line lists the skills it had.

- **Detected per task, not per project.** A prompt with UI words (Turkish too) or a brief that names UI files (`.tsx`, `.jsx`, `.vue`, `.svelte`, `.css`, `.scss`, `.html`, Flutter widgets, SwiftUI) is a UI task. A UI framework in the project is not enough, because the UI part of a project is often a small, separate piece of work. The profile is used only for UI tasks. The words also include page and site phrases such as "landing", "web site", "homepage", "ana sayfa", "sayfa yap", "ekran yap" and "html", and a prompt that names a UI file (`index.html`, `App.tsx`, `Hero.vue`, `app.scss`, a Dart widget) counts too. The hint and the Agent gate read the same list (`data/skill-catalog.json`, `scripts/ui-lib.sh`), so they agree; a false positive costs one hint or one denial.
- **Three profiles, kept in `.crew-chief/ui-profile.json`** (`{profile, motion 0-10, perfBudget, notes, refs[], pages?}`). The top level is the project's default; the optional `pages` object overrides `profile`, `motion`, `perfBudget` and `notes` for a file path or route glob (`"index.html"`, `"src/pages/menu/**"`). A new page with no matching entry just uses the default, with no question; the main session applies the matching entry and names the effective profile in the brief. When asking for the profile Claude lists the three neutrally: no "recommended" mark and no warning that one is too heavy, you pick and it follows. `immersive` means a real 3D scene (Three.js/WebGL, react-three-fiber for React, under the `web-3d-perf` rules), never a CSS or SVG imitation; an agent that cannot build it must say so in its report with the reason:

  | Profile | Meant for | Motion | Extra skills |
  |---|---|---|---|
  | `immersive` | Immersive 3D: a real WebGL scene within a performance budget | 8 | `animate`, `choreograph`, `web-3d-perf` |
  | `lively` | Lively: measured animation, smooth transitions | 3 | `animate` |
  | `calm` | Calm: almost no motion, fast and crisp | 0 | `remove-animations` |

  Profiles renamed: calm (was static-minimal), lively (was clean-practical), immersive (was performance-3d); the old names still work. The profile question shows these labels, in your language.

  The main session asks the profile, the motion value and the reference in one question before it reads or writes any project file, unless `.crew-chief/ui-profile.json` already exists (then it uses the file). Every UI brief must name the profile. Motion and the performance budget are free fields you can change in the file.
- **Preloaded skills and profile skills.** `ui-implementer` has `frontend-design`, `ui-ux-pro-max`, `thesvg` and `animation-performance` in its frontmatter (`skills:`), so their text is in its context from the first turn. The profile's extra skills, and `design-taste-frontend` for a landing page, a portfolio or a redesign, it loads itself with the Skill tool, from the brief and the start-of-agent context. The main session cannot be preloaded: its hint is short on purpose (a STOP-first step that asks the profile, motion and reference in one question, then hands all UI code to `ui-implementer`, plus the model line), and the ban list, checklist, motion bands and self-check reach the agents at start (`scripts/subagent-start.sh`). Brand logos come from `thesvg`, never hand-drawn.
- **The default look is banned.** Inter, Arial or the system font stack as the font; purple or indigo-to-blue gradients; a cream or beige background; a terracotta or orange accent; a serif headline chosen only because it is the default; three equal feature cards in a row; a centred hero over a gradient mesh. Each is allowed only when the profile, `DESIGN.md` or the brief chooses it on purpose; otherwise the agent picks a deliberate alternative and says what it chose.
- **A polish checklist** (after [jakub.kr](https://jakub.kr/writing/details-that-make-interfaces-feel-better), MIT, reworded): `text-wrap` balance and pretty, nested radius (outer = inner + padding), antialiased type, tabular numbers for changing figures, layered shadows instead of solid borders, a 1px outline on images, never `transition: all`, a press scale of about 0.96, touch targets of 44px, no horizontal overflow at 360px (header actions fit or collapse), icon stroke matching the text, and enter and exit motion that follows the profile's motion level and `prefers-reduced-motion`. The agent goes through it before it reports.
- **A reference before the first screen.** The main session asks once, with three options in your language: "I'll send one" / "Find some (ui-scout)" / "None". On "find" it briefs **`ui-scout`** (Sonnet, medium; it writes only under `.crew-chief/refs/`): it reads the README and `package.json`, researches what matters in the design of this kind of project (a coffee shop: menu legibility, hours and map visible, mobile first) as short checkable notes, finds three or four references (live sites of real businesses or products, and open galleries such as Awwwards, Godly and Land-book; nothing login-gated), looks at each with Claude in Chrome (its own tab, never yours; if its tools do not load, headless Chrome, else `curl` for the HTML) and saves desktop (1440) and mobile (390) screenshots with the same `ui-shot.mjs` plus `.crew-chief/refs/REFS.md` (per reference: URL, date seen, what to take, what not to copy, ranked, #1 with a reason, and the domain notes). You then pick from the candidates in one question; no answer (you are away, night mode) means its #1. The picked paths go into every UI brief and into `refs[]`; the agent opens each with Read before designing and reports what it took (layout, density, type feel). References are inspiration only, never copied 1:1, and brand assets and fonts belong to their owners. `ui-scout` and `ui-tester` never run on the same browser at the same time. Under `immersive` it may also offer the optional `reanimate` skill to reproduce an animation from a live site; it is installed only with your yes (needs Bun and Chromium, about 250 MB).
- **Motion bands and a visual self-check.** A motion value means a concrete list, and a value inside a band must deliver all of it: 0-1 no motion (colour and opacity on hover and focus only); 2-3 scroll reveal of the sections plus hover and press feedback; 4-6 all of that plus a staggered hero entrance, a micro-interaction on every interactive element, one ambient loop and choreographed section transitions; 7-8 plus scroll-linked scenes, parallax and page or view transitions; 9-10 plus a continuous scene and 3D/WebGL effects. Every band has a `prefers-reduced-motion` fallback and uses only transform and opacity. Before `ui-implementer` reports done it runs `scripts/ui-shot.mjs` (Node 22+, Chrome over the DevTools protocol, because plain headless Chrome cannot lay a page out narrower than about 500 px): a 1440 screenshot, a real 390 px mobile screenshot and the horizontal overflow at 1440, 390 and 360 (`scrollWidth > innerWidth`); it fixes any overflow, then compares the animations the page really has with the band's list; the report carries the screenshot paths, the overflow numbers and the band check. The screenshots go to `.crew-chief/check/` (or the OS temp folder), never into the source: add `.crew-chief/check/` to your `.gitignore`. Without a headless browser the check is reported as not verified.
- **A gate that denies once.** `scripts/ui-brief-check.sh` (PreToolUse on `Agent`) denies a UI task that goes to `implementer`, `implementer-hard`, `mechanic`, `general-purpose` or an untyped call, or a brief for `ui-implementer` that does not name the profile. The reason goes to the model; the identical retry within four hours passes. It does not rewrite the prompt. Read-only agents (`ui-scout` included) and agents this plugin does not know pass untouched. `CREW_CHIEF_UI_GATE=off` turns it off. It needs `jq`; without it, or when its input cannot be parsed, it lets the call through.
- **A write gate for UI files.** Text alone did not keep the main session from writing `index.html` itself in Claude's default look, so `scripts/ui-write-check.sh` (PreToolUse on `Write`, `Edit` and `MultiEdit`) denies the first write of a UI file (`.tsx`, `.jsx`, `.vue`, `.svelte`, `.css`, `.scss`, `.html`, and a `.dart` file that looks like a Flutter widget) in a project without `.crew-chief/ui-profile.json`. The reason says to set the profile, ask for a reference image and hand the UI code to `ui-implementer`; if it is only a tiny fix to an existing UI file, the identical call (same tool, same path) passes on retry within four hours. Once the profile file exists it never denies. Writes into `.crew-chief/` and `ui-implementer`'s own writes always pass. Same switch (`CREW_CHIEF_UI_GATE=off`) and same fail-open rules as the Agent gate. Not yet seen in a live session.
- **Your own changes: `~/.claude/crew-chief-ui.json`**, same shape as `data/ui-policy.json`, merged on top of it (objects key by key; lists and strings are replaced, so a `base` list you write replaces the shipped one). Use it to change the mandatory skills, the profiles, the ban list or the checklist. The plugin never writes that file.
- **`web-3d-perf`** (written for crew-chief, not a copy) is the frame-budget skill for React Three Fiber, Three.js and WebGL work: write the budget first (frame time, draw calls, memory, weakest device), cap the pixel ratio, render on demand when the scene is still, pause offscreen and in a hidden tab, no `setState` or allocation per frame, instancing, disposal, lazy loading, a reduced-motion fallback, and how to measure. It is a mandatory extra skill under `immersive` and can be loaded on its own for any 3D or heavy canvas task.

The UI skills the profiles use are the bundled third-party copies listed in `THIRD_PARTY_NOTICES.md`.
