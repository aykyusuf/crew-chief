# Privacy and what the mod does

No telemetry; what crew-chief reads, runs, writes and stores, and the two network exceptions.

[← README](../../README.md) · [Türkçe](../rehber/privacy.md)

## Privacy

Crew Chief collects and sends no data. Its hooks run locally and print text or an exit code. They read the hook input Claude Code passes them (the session's project path and id, your prompt to spot `/crew-chief:crew-mode` and to match the skill hints, and the Bash command or file path a subagent is about to use) and, at session start, look at the project itself: whether it is a git repository, whether `CLAUDE.md` or handoff files exist, and which stack files (`pubspec.yaml`, `package.json`, ...) it has, and which skills are installed on your machine, only to decide about the skill offer and hints.

What is stored stays in `~/.claude/plugins/data/<plugin>/` on your machine, which Claude Code deletes when you uninstall the plugin: your answer to the handoff offer (`handoff-offers.tsv`: a line per answer, the project path and `installed`, `never`, or `later` with a timestamp; the latest line per project counts), when the handoff files were last checked for staleness (`handoff-checks.tsv`: the project path and a timestamp, at most one line a week per project), a small marker that the mod asks the handoff question itself (`mod-offer-active`: a timestamp), the plugin version you were last told about (`last-seen-version`), the plugin version for which it last checked your Claude Code version (`claude-version-checked`), and small per-session marker files for solo mode (`modes/`), the stale-session notice (`stale-notified/`) and the skill hints already given (`skill-hints/`), named by session id and pruned when newer ones are written once they are two weeks old, and your answers to the [skill offer](skills-and-reports.md) (`skill-offers.tsv`: project path, kind of work, and `installed`, `never`, or `later` with a timestamp). Subagent progress files and long reports live in your temp directory (`crew-chief-progress/`, `crew-chief-reports/`), outside the plugin's store.

The plugin writes into your project only when you say yes: `/crew-handoff` creates the handoff files you confirmed, `/crew-tidy archive` appends old entries to `PROGRESS-archive.md` and shortens `PROGRESS.md` after you confirm, and at a compaction you approved, Claude (not the plugin's scripts) updates `STATUS.md`, `tasks.json` and `PROGRESS.md`.

Beyond that, the plugin keeps in its data folder: `compact-summaries/` (the raw summary of each compaction, last 5, readable only by you) and, only if a compaction ever lost transcript lines, `transcripts/` (a copy of the session transcript taken before later compactions, last 3, readable only by you); a plugin loaded from a plain directory, without a data folder, uses `${TMPDIR:-/tmp}/crew-chief-compact/` instead.

The files it writes outside the plugin's store are your `~/.claude/settings.json` (plus `crew-chief-subagent-row.sh`, a backup, and a marker next to it), once, to add the panel row; see [Panel row installer](panel.md#panel-row-installer); and `~/.claude/crew-chief-guard.json`, once, on the first interactive session when it is missing, and later only by `/crew-guard on` or `off`; see [Command guard](guard.md).

The saver reads your plan usage, context size, and the first lines of your prompts (only to tell Turkish from English) inside Claude Code, keeps just the detected language (`tr` or `en`), your answer to the advisor offer (`answered`, `never`, or a pause time), whether the transcript kept its lines in a compaction (`transcript_kept`) and the shortest and longest idle gaps it has seen the prompt cache expire or survive (`cache_hint`) in the plugin's store, and sends nothing anywhere.

The compact flow reads your handoff files, the instruction and memory files Claude Code loaded, the session transcript's line count (`wc -l`) and, to copy it if needed, the transcript file itself; none of that leaves your machine.

The `/crew-agents` pane reads a subagent's transcript only while it is open and only for the agent you picked; it shows it there and keeps it in memory until the pane closes, never on disk, in a log or on the network. The same holds for an agent you open in the band: its transcript is shown only under its row and kept in memory only while it is open; a message you write to an agent goes to that agent alone (`$.session.send`) and is not logged or kept.

The [command guard](guard.md) reads `~/.claude/crew-chief-guard.json` at session start and, only when it is on, the text of each command and file path. It writes that file once, on the first interactive session when it is missing, and afterwards only when you type `/crew-guard on` or `off`; in the plugin's store it keeps only `guard_setup` (`done` or `failed`).

There is no telemetry or network access in the plugin itself. Two exceptions, both only when you use them: the bundled theSVG skill has the agent fetch icons from cdn.jsdelivr.net, and a research run (`/crew-chief:crew-research`, `/crew-chief:crew-lint`) fetches the pages the researchers cited to check each quote (`scripts/source-check.mjs`: read only, sends no project data, refuses private and loopback addresses, never prints page text).

Bug reports go to [GitHub issues](https://github.com/aykyusuf/crew-chief/issues).

## What the mod does with your machine

For reviewers and for you. Everything below happens inside Claude Code on your machine; the mod has no network access and sends nothing anywhere.

| What | Where | Why |
|---|---|---|
| **Reads files** (`$.fs.read`, `exists`, `list`, `stat`) | The project's `STATUS.md`, `tasks.json`, `PROGRESS.md`; the instruction and memory files Claude Code loaded (the list `/context` shows), only for `/crew-tidy`; file times for the compact gate | To check the summary against your pinned rules and open tasks, to audit context, to wait until `STATUS.md` was updated |
| **Reads settings** (`$.settings.read`) | Only the `language` and `advisorModel` keys | To speak your language and to know whether the advisor offer applies. It never reads API keys, tokens or any credential |
| **Reads environment** (`$.env.get`) | `HOME` (`USERPROFILE` when `HOME` is unset), `TMPDIR`, `LANG`, `OS`, the `CREW_CHIEF_*` switches, and a few `CLAUDE_CODE_USE_*` flags | Paths, language, switches, whether a cloud provider route is in use, and whether this is Windows (`OS=Windows_NT`, for the agent row) |
| **Runs programs** (`$.process.run`) | `wc -l <transcript>` (count lines before and after a compaction); `git status --porcelain` (count uncommitted files, shown in the compact question); `chmod 600 <file>` (make its own backups private); `rm -f <old backup>` (delete only its own backups beyond the newest 5 or 3); `mkdir -p`, `cp -p <transcript> <backup>` (only if a compaction ever lost transcript lines); `jq --version` (once a session, only in a plain terminal, to know whether the shell panel row can draw). The arguments are paths the mod computes, not text from the conversation | Backups and the transcript check |
| **Runs a slash command** | `/advisor`, once, only after you said yes to the [advisor offer](advisor.md) | To turn the advisor on for you |
| **Submits prompts** (`$.prompt.submit`) | Two fixed texts, framed as coming from crew-chief (never as your own words): "update the handoff files" after you approved a compaction, and "continue where you left off" at a limit reset you approved. They contain no file contents and no conversation text | To carry out what you approved |
| **Writes files** (`$.fs.write`) | Its own data folder (`compact-summaries/`); and, only when you confirm `/crew-tidy archive`, `PROGRESS.md` (shortened) and `PROGRESS-archive.md` (the old entries). It never writes your instruction files, settings, or build files | Backups; the archive you asked for |
| **Registers a tool** | `crew_compact_checkpoint`, which only notes that a phase ended and tells Claude to carry on; you are asked after the turn | The phase-boundary proposal |
| **Answers its own questions** (a `tool.call` hook on `AskUserQuestion`) | Only the dialogs the mod itself opened: after `CREW_CHIEF_ASK_TIMEOUT_MIN` minutes (default 20) without an answer it answers with the question's safe choice (never yes, never *Don't ask again*). Claude's own `AskUserQuestion` calls pass through untouched | So an unattended session is not held by a plugin question |
| **Draws one status line** (`$.ui.status`), reads the session's surfaces (`$.session.surfaces`) and agent list (`$.agent.list`) | The [agent row](panel.md#agent-row-status-line): each running subagent's name, model, effort and tokens, cleared when none runs | So the model and effort of subagents show on the Desktop app, VS Code and Windows too. Nothing is stored or sent |
| **Reads a subagent's transcript** (`$.session.messages({ agentId })`) | Only while the `/crew-agents` pane is open, only for the agent picked in it: its last messages, tool calls and results, shown in the pane. Kept in memory for the open pane alone and dropped when it closes; the report an agent hands back is kept in memory for the session (at most 4,000 characters each) | So you can look inside a subagent on the Desktop app too. Never written, stored, logged or sent |
| **Reads a subagent's transcript in the band** (`$.session.messages({ agentId })`) | Only for the agents you opened with a click on their band row (at most 4 at once): when you open one, then at most every 1.5 s while it runs and does something, and once more when it ends (a finished agent is not read again until it runs again). Its last 5 steps or its report are drawn under its row; the drawing itself never reads | So you can follow an agent without opening a pane. Kept in memory only while it is open; never written, stored, logged or sent |
| **Shows an agent's transcript** (`$.ui.view`) | Only when you press *Full view* under an open agent (`{ agentId }`) or *Back to the main chat* (`{}`); Claude Code allows it only as the answer to your own press | The whole transcript in the main view. While it is shown, what you type in the prompt goes to that agent |
| **Sends a message to a subagent** (`$.session.send`) | Only the text you typed in the field under an open agent and sent with Enter: never empty, at most 2,000 characters. A running agent reads it at its next tool turn; a finished agent is started again by it (that costs tokens), so the band asks first and the safe answer (*Don't send*, also after 60 s without an answer) sends nothing | So you can steer an agent from the band. The text is not logged, stored or kept after it is sent |
| **Raises a notification** (`$.ui.toast`, `$.ui.notify`) | When a subagent finishes: its name, how long it ran, its tokens and tool calls, through your own notification channel (`preferredNotifChannel`, after your `Notification` hooks) | So the end of a subagent is not missed. `notify.agent` / `notify.native` off turn them off |
| **Command guard** (a `tool.call` hook; on after the first interactive session) | Unless `CREW_CHIEF_GUARD=off`, reads `~/.claude/crew-chief-guard.json` once per session start (`HOME`, or `USERPROFILE` on Windows). Once, on the first interactive session with no such file (and unless `CREW_CHIEF_GUARD_AUTOSETUP=off`), writes it with default rules and stores `guard_setup` (`done` or `failed`) in the plugin's store so a deleted file is never recreated; afterwards writes it only when you type `/crew-guard on` or `off`. Only when it is on: reads the text of each Bash command and file path; may refuse a tool call (with a reason for Claude and a toast for you, which shows at most 80 characters of the command) or add a warning after it; reads the agent list only to know whether an agent is read-only. No network, nothing stored or written; the ssh gate's memory ends with the session | The [command guard](guard.md) |
| **Compaction hooks** | Adds a summarizer brief to a compaction (`session.compact`), and starts a compaction only after your yes | Nothing important lost |
