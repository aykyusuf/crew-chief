# Night mode: `/crew-chief:crew-night`

Claude keeps working until a deadline you set while you sleep, within hard limits, and leaves a report.

[← README](../../README.md) · [Türkçe](../rehber/night.md)

Claude keeps working while you sleep, until a time you set, and you get a report in the morning.

- **Start:** `/crew-chief:crew-night until 07:00` (or `for 6h`). Claude reads the project, tells you what it would do and what is critical, and asks everything at once: scope, goal and how to check it, the deadline, git for this night (commit per task, no commits, or a branch you name), outward actions (closed by default; **open** lets the night push, deploy, run CI and change servers, each one logged for the report, with crew-chief's command guard still stopping risky ones once), forbidden commands, decision rights. A question you leave for 20 minutes closes by itself (`NO_ANSWER`), and that item is parked, not guessed. `/crew-chief:crew-night dry-run` is a 20-minute rehearsal.
- **During the night:** Claude decides small, reversible things alone and logs each in `DECISIONS.md` with how to undo it; product choices, missing secrets and anything irreversible, outward or paid are parked in `QUESTIONS.md` (with "ready to run" commands where it prepared one). A Stop hook keeps the session going until the deadline and switches to wrap-up 30 minutes before it; three Stop events in a row with no progress end the night as stalled. Enforced by code (in bypass mode the hooks are the only gate): no `git push`; no GitHub writes (`gh pr merge/create/comment`, `gh release`, ...), deploys or publishes (vercel, netlify, fly, firebase, kubectl apply, helm, terraform apply, npm publish, docker push, ...), cloud changes (aws, gcloud, az verbs that create, delete, update, start, stop or deploy), server changes over ssh (`rm`, `systemctl restart`, a database client, `sudo`, a redirect ...) or uploads (scp/rsync to a host, sftp); no `rm -r` outside the repo. Reading stays allowed: `ssh host 'tail log'`, `aws s3 ls`, `gcloud ... list`, downloads with scp/rsync; your forbidden list; at most 20 subagents, none on Fable, no questions to you after the start, permission prompts denied. Policy for the model (repeated in every Stop reason): 3 attempts per task, a task that eats 40 percent of the night is parked.
- **crew-chief's own questions are silent at night:** a compaction is approved by itself (the hook lets the turn end, the handoff files are updated, the night resumes), the plain saver turns on by itself if the limit gets tight (never ultra), offers are skipped. When the 5-hour window or the weekly limit reaches 95 percent, no new work starts and the night wraps up. Each of these goes into `events.log`.
- **Files:** `night/<session>/` at the repo root, one folder per session (several sessions can run nights in the same repo), hidden through `.git/info/exclude` (no project file changes): `NIGHT.md` (the contract), `QUESTIONS.md`, `DECISIONS.md`, `events.log`, `REPORT.md`, `state.json`. On macOS `caffeinate` keeps the machine awake until the deadline. Finished nights are cleaned at the next start: state and logs after 7 days, `REPORT.md` and `DECISIONS.md` after 30.
- **End:** at the deadline the night ends by itself; `REPORT.md` lists what needs you first, then what was done (with evidence and commits), what was decided without asking and what it affects, what was not done and why, and how to undo the night. If Claude wrote no report, a script writes one from the files. The next session start shows the report once. `/night status` and `/night off` work any time; a night cut by a crash or a closed lid continues with `/crew-chief:crew-night resume` until the original deadline.
- Not yet seen live in the Desktop app; the 20-minute close of the opening questions is checked only with mocks.
