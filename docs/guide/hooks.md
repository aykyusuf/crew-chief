# What it runs

The hooks and scripts crew-chief ships, when each runs and what it does.

[← README](../../README.md) · [Türkçe](../rehber/hooks.md)

Everything is plain, readable shell in this repo. Nothing is sent over the network.

| Component | When | What it does |
|---|---|---|
| `scripts/session-policy.sh` | SessionStart (startup, resume, clear, compact) | Prints the ~2 KB routing policy into the session context. On a fresh start in a git repository without handoff files, also adds the one-time [handoff offer](handoff.md); it never writes files itself |
| `scripts/install-row.sh` | SessionStart (startup only) | Adds `subagentStatusLine` to `~/.claude/settings.json` once, see [the row installer](panel.md#panel-row-installer) |
| `scripts/subagent-row.sh` | Agent panel refresh, while subagents run | Reads the panel's row data (agent type, model, effort, tokens, start time) and prints the row text: elapsed time, and the reported percent, step and delay reason while the agent's report is fresh (see [Progress in the panel](panel.md#progress-in-the-panel)). Needs `jq`; without it the default rows stay |
| `scripts/skill-hint.sh` | UserPromptSubmit | Adds a one-line "load the X skill" reminder when the prompt matches a kind of work in `data/skill-catalog.json` and a preferred skill is installed. Remembers per session which hints it gave (`${CLAUDE_PLUGIN_DATA}/skill-hints/`). Needs `jq` |
| `scripts/skill-offer.sh` | SessionStart (startup only) | Prints the one-time [skill offer](skills-and-reports.md) when the project's stack has hand-checked skills and none is installed. Answers are kept in `skill-offers.tsv`. Needs `jq` |
| `scripts/skill-lib.sh` | (sourced) | Lists the installed skills for the two scripts above |
| `scripts/progress-hook.sh` | PostToolUse (subagent calls only) | Keeps one small file per subagent in `${TMPDIR:-/tmp}/crew-chief-progress/` (tool count, last tool, a slow-call note, and the agent's own `crew-progress` report with the tool count and time when it was sent); files older than 12 hours are removed. It prints nothing: the reminder is sent by the mod. Needs `jq` |
| `scripts/subagent-start.sh` | SubagentStart | Gives every subagent the progress-report rule as starting context, so it no longer depends on each brief; `ui-implementer`, `ui-designer` and `ui-scout` also get the UI profile (the first two the motion bands, the implementer the self-check). Needs `jq` |
| `scripts/ui-brief-check.sh` | PreToolUse on Agent | The one-time [UI gate](ui.md): a UI task that goes to another writing agent, or whose brief does not name the UI profile, is denied once; the identical retry passes. The same policy file also feeds the UI rules that `skill-hint.sh` and `subagent-start.sh` add. Needs `jq` |
| `scripts/ui-write-check.sh` | PreToolUse on Write, Edit, MultiEdit | The one-time [UI write gate](ui.md): writing a UI file (`.tsx` `.jsx` `.vue` `.svelte` `.css` `.scss` `.html`, a Dart widget) in a project that has no `.crew-chief/ui-profile.json` is denied once; the identical retry passes, and so does everything once the profile exists. Needs `jq` |
| `hooks/register.js` (a mod) | Session events | The [token saver](token-saver.md): reads `$.session.usage()` for your plan limits and context size, asks with `$.ui.ask`, and lowers subagent effort in `turn.step` while the saver is on. Keeps saver state in memory only; remembers the language and your answer to the advisor offer. Also offers `/advisor` once (see [Advisor offer](advisor.md)) |
| `hooks/src/*.js` (the mod's parts, joined into `hooks/register.js`) | Session events | The [compact flow](compact.md), [limit resets](limits-and-audit.md#limit-resets), and [`/crew-tidy` and `/crew-report`](limits-and-audit.md#context-audit-and-report). The directory that reviews plugins reads the mod file by itself, so everything that touches `$` is joined into the one readable `hooks/register.js` by `tools/build_mod.py` (edit `hooks/src/`, then run it; CI checks it is current). Pure helpers that never see `$` stay separate: `compact-logic.mjs`, `tidy-logic.mjs`, `report-logic.mjs`, `saver-logic.mjs`, `saver-i18n.mjs`, `coord.mjs` |
| `scripts/compact-restore.sh` | SessionStart (compact) | After a compaction, prints the user's pinned Constraints, Now, Next, Decisions, the latest failed attempts and the open tasks from the project's handoff files (about 8000 characters at most) and the transcript path. Reads only; `CREW_CHIEF_RESTORE=off` turns it off |
| `scripts/mode-guard.sh` | UserPromptSubmit and UserPromptExpansion; PreToolUse on Agent | `record`: when your prompt is `/crew-chief:crew-mode <mode>`, remembers the mode for this session. `check`: while that mode is `solo`, blocks subagent spawns (exit 2). No recorded mode means everything passes |
| `scripts/plugin-notices.sh` | UserPromptSubmit | On the first prompt after an update, shows the version change and the first lines of its CHANGELOG section. In a session that still runs a replaced copy, says so once instead. Both print a `systemMessage` for you |
| `scripts/readonly-guard.sh` | PreToolUse on Bash, Write, Edit | Reads the hook input; if the caller is `crew-chief:scanner`, `deep-reader`, `reviewer`, `planner`, `ui-smoke`, `ui-designer`, or `ui-scout`, blocks commands that write files, change git state, or install packages, and any file write outside `${TMPDIR:-/tmp}/crew-chief-reports/` (exit 2). Two exceptions: `ui-designer` may write `.md` files under `.crew-chief/design/`, and `ui-scout` may write `.md`, `.png`, `.jpg` and `.webp` files under `.crew-chief/refs/` plus one headless Chrome screenshot command into that folder (a single simple command, allow-listed flags, an http(s) URL, a throwaway `--user-data-dir` under the temp folder; no pipes or redirects). Both are checked for symlinks and `..` Every other caller passes through untouched |

With `/crew-setup` (no plugin), the same guard is copied to `.claude/hooks/crew-chief-guard.sh` and wired through `.claude/settings.json` with `--project`, matching the bare agent names. It is not put in the agents' frontmatter on purpose: Claude Code skips frontmatter hooks of project agents until the folder's trust dialog is accepted, and never runs them in `-p` sessions.

The guard is a pattern check, not a sandbox: it blocks the common ways to write and errs on the side of blocking (for example a `>` inside a quoted awk expression). It does not try to catch deliberately obfuscated commands.
